## 📘 Definición

Un **trigger** (disparador) en una base de datos es un tipo especial de **procedimiento almacenado** asociado a una tabla, que se ejecuta automáticamente al realizarse una operación básica sobre esta (`INSERT`, `DELETE` o `UPDATE`).

- La operación básica que activa al trigger se conoce como **disparador**.
- Se usan para mejorar la administración de la base de datos sin depender de que el usuario ejecute sentencias SQL específicas para ello.
- Permiten generar valores de columnas, prevenir errores de datos, sincronizar tablas, modificar valores de una vista, realizar auditorías de seguridad, entre otros usos.
- Pueden llamar a otros procedimientos y disparar otros triggers, **pero no admiten parámetros** y **no pueden ser invocados desde otros procedimientos**.

> Un trigger está asociado a una tabla y **no se puede ejecutar con un `SELECT`**. Se activan automáticamente cuando quedan programados; no aparecen listados junto a las funciones y procedimientos.

> Si varias personas trabajan sobre la misma base de datos, los triggers pueden usarse para llevar **auditorías de seguridad** de forma automática.

## 🧩 Características

| Característica | Detalle |
|---|---|
| Límite en MySQL | Máximo **6 triggers** por tabla |
| Temporalidad | `BEFORE` (antes) o `AFTER` (después) |
| Acción / disparador | `INSERT`, `DELETE`, `UPDATE` |
| Granularidad | `FOR EACH ROW` → se ejecuta para cada fila afectada |

| Tipo de Trigger | Momento de activación |
|---|---|
| `BEFORE INSERT` | Antes de insertar un registro en la tabla |
| `AFTER INSERT` | Después de insertar un registro en la tabla |
| `BEFORE UPDATE` | Antes de actualizar los datos en la tabla |
| `AFTER UPDATE` | Después de actualizar los datos en la tabla |
| `BEFORE DELETE` | Antes de borrar un registro en la tabla |
| `AFTER DELETE` | Después de borrar un registro en la tabla |

---

## ✍️ Sintaxis

```sql
DELIMITER |
  CREATE TRIGGER nombre
    {BEFORE | AFTER}              -- Temporalidad del evento
    {INSERT | DELETE | UPDATE} ON <tabla>
    [FOR EACH ROW]                -- Granularidad
  BEGIN
    cuerpo del trigger
  END;
|
DELIMITER ;
```

## 🔁 Variables OLD y NEW

| Variable | Uso |
|---|---|
| `OLD` | Contiene el valor **anterior** de la fila (disponible en `UPDATE` y `DELETE`) |
| `NEW` | Contiene el valor **nuevo** de la fila (disponible en `INSERT` y `UPDATE`) |

## 🕵️ Caso 1: Auditoría de precios

Registra en `auditoriaPrecio` cada vez que el precio de venta de un producto cambia.

```sql
DELIMITER $$
CREATE TRIGGER auditoria
AFTER UPDATE ON productos
FOR EACH ROW
BEGIN
    IF OLD.precioV <> NEW.precioV THEN
        INSERT INTO auditoriaPrecio
        VALUES (USER(), NOW(), OLD.codigoProducto, OLD.precioV, NEW.precioV);
    END IF;
END $$
DELIMITER ;
```

> `<>` significa **diferente** en MySQL.

## 📦 Caso 2: Aumentar stock (compra)

Cuando se compra cierta cantidad de un producto (`detalle_compra`), el stock del producto debe aumentar.

```sql
DELIMITER $$
CREATE TRIGGER aumentarStock
AFTER INSERT ON detalle_compra
FOR EACH ROW
BEGIN
    UPDATE productos
    SET stock = stock + NEW.cantidad
    WHERE idProducto = NEW.idProducto;
END $$
DELIMITER ;
```

---

## 📉 Caso 3: Disminuir stock (venta)

Caso contrario: al venderse un producto (`detalle_venta`), el stock debe disminuir.

```sql
DELIMITER $$
CREATE TRIGGER disminuirStock
AFTER INSERT ON detalle_venta
FOR EACH ROW
BEGIN
    UPDATE productos
    SET stock = stock - NEW.cantidad
    WHERE idProducto = NEW.idProducto;
END $$
DELIMITER ;
```

## 🚫 Caso 4: Validar stock con SIGNAL

Antes de insertar una venta, valida que exista stock suficiente; si no, lanza un error controlado.

```sql
DELIMITER $$
CREATE TRIGGER validarStock
BEFORE INSERT ON detalle_venta
FOR EACH ROW
BEGIN
    DECLARE stockActual INT;

    SELECT stock
    INTO stockActual
    FROM productos
    WHERE idProducto = NEW.idProducto;

    IF NEW.Cantidad > stockActual THEN
        SIGNAL SQLSTATE '45000'
        SET message_text = 'Stock insuficiente';
    END IF;
END $$
DELIMITER ;
```

| Elemento | Función |
|---|---|
| `SIGNAL` | Se asemeja a un `try/catch`: provoca un error de manera controlada |
| `SQLSTATE` | Código de error, según el tipo de error que se quiera representar |
| `message_text` | Mensaje que se imprime cuando se captura el error |

## 🛠️ Comandos útiles

```sql
SET SQL_SAFE_UPDATES = 0;
```


> Este comando **desactiva el modo seguro de MySQL**, útil cuando se necesita hacer `UPDATE`/`DELETE` sin cláusula que use la llave primaria (común al probar triggers).

## ✅ Buenas prácticas y errores comunes

| Buenas prácticas | Errores comunes |
|---|---|
| Usar `FOR EACH ROW` cuando se necesita granularidad por fila | Olvidar cambiar el `DELIMITER` antes de definir el trigger |
| Validar datos con `BEFORE INSERT`/`BEFORE UPDATE` antes de guardarlos | Intentar invocar un trigger manualmente (no es posible) |
| Usar `SIGNAL` para mensajes de error claros y controlados | Confundir `OLD` y `NEW` según el tipo de operación |
| Documentar el propósito de cada trigger (auditoría, stock, validación, etc.) | Superar el límite de 6 triggers por tabla en MySQL |
